## 1. 目的とスコープ

### 目的
ポスティング部門の「諸経費・買掛・売掛の登録」「配布員（業務委託）の報酬計算と請求書発行」「号別明細へのコスト集約」「経理提出用データ出力」を自動化・一元管理し、Excel転記や目視確認の工数をゼロにする。

すべての入力を **案件名（号）をキー** に串刺しし、①②で入力したものが③号別明細・④経理出力へ**自動集約**される（オーナー要望の「前提」）。

### 第1弾（MVP）に含むもの
- 機能①：経費・買掛・売掛の登録（小口レシートOCR／買掛・売掛の登録・請求書OCR／手入力）
- 機能②：業務委託費の管理＋『業務完了報告書兼請求書』のExcel生成（個人配布員）
- 機能③：号別明細への自動集約（コスト可視化・収支）
- 機能④：経理提出用データ出力（期間指定でExcel/CSV）
- マスタ管理（案件／費目／取引先／売掛先／配布委託先）

### 第2弾以降に回すもの（本設計では作らない）
- 資料作成 変換表（関西ぱどCSV→あて紙／報告書／集計表／実績表、アドバリューのエリア被り判定、リビングプロシード配布依頼書→あて紙）
- AWS App Runner への恒常公開（テレアポアプリと同じ手順で後日）
- 経理（吉田さん）への自動メール送付（MVPは手動DL→送付）

## 3. データモデル（SQLite）

すべて「案件名」で串刺しにできるよう設計する。金額は税込を基本とし、税抜が必要な項目は別列で保持。

### マスタ（すべて画面で追加・編集・無効化が可能）
- **案件マスタ** `projects`：`id`／`name`（例：関西ぱど：京阪北版、関西ぱど：京阪南版、アドバリュー、リビングプロシード、その他）／`active`
  - 初期プリセット：関西ぱど京阪北版・京阪南版・アドバリュー・リビングプロシード・その他
- **費目マスタ（小口用）** `expense_categories`：`id`／`name`（駐車場代・飲み物代・その他）／`active`
- **取引先マスタ（買掛先）** `payables_vendors`：`id`／`name`／`default_category`（家賃・電気・ゴミ収集・派遣・リース・コピー代・配布・警備・その他）／`active`
  - 初期プリセット（`KPS 売掛・買掛 明細表`のマザー相当）：京阪総合サービス（ゴミ収集）／大東建託パートナーズ（家賃）／NTTファイナンス（電話）／NTTコミュニケーション（プロバイダ）／関西電力（電気）／スペースリーダー（機械警備）／トヨタレンタリース大阪（リース）／ネクストレベル（派遣）／キャノンMJ（コピー代）／CLOVER JAPAN（配布）／配夢 ほか
- **売掛先マスタ** `receivables_clients`：`id`／`name`／`active`
  - 初期プリセット：関西ぱど北大阪営業部／進和プロモーション大阪支社／アド・バリュー／リビングプロシード
- **配布委託先マスタ（個人）** `distributors`：`id`／`name`（個人名）／`kind`（**業務委託／自社社員／アルバイト**）／`active`

### データ表
- **小口経費** `petty_cash`：`id`／`date`／`category_id`（費目）／`amount`（税込）／`project_id`（案件・任意）／`memo`／`source`（ocr/manual）／`created_at`
- **買掛明細** `payables`：`id`／`month`（YYYY-MM 月度）／`vendor_id`（取引先）／`amount`（税込）／`original_status`（**原本区分：原本あり〇／本社／クレジット／振込用紙／なし**）／`note`（備考・内容）／`project_id`（案件・任意。配布業者なら号）／`source`（ocr/manual）／`created_at`
- **売掛明細** `receivables`：`id`／`month`（YYYY-MM）／`client_id`（売掛先）／`amount`（税込）／`note`（備考・号）／`project_id`（案件・任意）／`created_at`
- **委託請求（ヘッダ）** `contract_invoices`：`id`／`distributor_id`（配布員）／`issue_date`（発行日）／`period_from`／`period_to`（配布業務期間）／`created_at`
- **委託明細行** `contract_invoice_lines`：`id`／`invoice_id`（→委託請求）／`project_id`（品名・号数＝案件名）／`report_qty`（報告数）／`unit_price`（単価）／`amount`（計＝報告数×単価）／`remark`（**配布／挟み込み／交通費／手当／その他**）
- **号別手入力** `issue_manual_costs`：`id`／`project_id`（案件）／`content`（内容：自社社員配布分 等）／`amount`／`created_at`

## 4. 機能① 経費・買掛・売掛の登録

「経費・買掛・売掛」ページに **`小口` `買掛` `売掛` `配布委託費`** のボタンを置き、選ぶと専用フォームが開く。`配布委託費` は機能②へジャンプ（個人配布員の完了報告書兼請求書はそちらで処理）。

### 4.1 小口（レシートOCR＋手入力）
- レシート/領収書の画像（JPG/PNG）をアップロード → **Bedrock Claude（画像対応）** が「日付・金額・品目」を抽出 → フォームに自動反映。
- ユーザーが **費目（マスタ選択）** と **案件名（任意・マスタ選択）** を補い、**金額・日付は必ず画面で確認・修正できる**うえで登録。
- 手入力のみでの登録も可。

### 4.2 買掛（固定費＋法人業者。明細表の買掛分に相当）
- **取引先（マスタ選択）・月度・金額(税込)・原本区分（〇/本社/クレジット/振込用紙/なし）・備考・案件名(任意)** を登録。
- **常連取引先がプリセットで一覧に並ぶ**ので、毎月マザーをコピーする作業を廃し、金額だけ入れる運用にする。
- **請求書OCR：複数枚まとめてアップロード**し、AIが各請求書の金額（と取引先候補）を抽出→一覧で確認・修正→まとめて登録（月80枚の手入力を解消）。
- 法人配布業者（CLOVER JAPAN 等）もここで買掛登録。配布案件に紐づくなら案件名（号）を付けて③へ集約。

### 4.3 売掛（売上。明細表の売掛分に相当）
- **売掛先（マスタ選択）・月度・金額(税込)・備考(号)・案件名(任意)** を登録。KPSの売上として蓄積。
- 号別明細で「売上−コスト」の収支を出すために、可能なら案件名を紐づける。

## 5. 機能② 業務委託費の管理 ＆ 請求書生成（個人配布員）

### 入力
- **配布員（配布委託先マスタから選択）**。
- **発行日**：今日の日付を自動入力（編集可）。
- **配布業務期間**：カレンダーUIで開始日・終了日を選択。
- **明細テーブル（複数行追加可）**：
  - 品名・号数 ＝ **案件名（案件マスタから選択式）**。号別明細と名称を一致させる。
  - 報告数（数量・手入力）／単価（手入力）／計（＝報告数×単価・自動）
  - **備考（プルダウン：配布／挟み込み／交通費／手当／その他）**
- **配布部数（部）＝ 備考が「配布」または「挟み込み」の報告数合計**（自動）。

### 出力（invoice_excel.py）
- 蓄積データを **『業務完了報告書兼請求書テンプレート.xlsx』** の指定セルへ流し込み、Excelでダウンロード。
- テンプレ構造（実測）：
  - A1 タイトル／A3 宛名「株式会社ケイピーエス 様」／F3 発行日／A7 ご請求金額（税込・自動合計）
  - A10 配布業務期間／12行目ヘッダ（内訳・品名号数[B:C結合]・数量・単価(税込)・計）／13〜18行が明細
  - E20「配布部数」F20「部」（→ **報告数の合計に置換**、ラベルも「報告数」に寄せる）
  - A22 免責文／F25〜 ケイピーエス記載欄（画像データ送付済み・現金振込支払い済み）
- テンプレの様式・数式・書式を壊さないため、テレアポの完了報告書と同様に**値で流し込み**、様式は保持する。
- 作成した請求書は一覧に蓄積し、**配布員別の報酬一覧**も表示。

## 6. 機能③ 号別明細への自動集約

- 案件名（号）を選ぶと、その号に紐づくコストを内訳つきで集約表示：
  - **小口経費**（費目・金額）／**買掛**（取引先・金額。配布業者等）／**業務委託費**（配布員別・金額）／**号別手入力**（自社社員配布分 等）
- **自社社員配布分などは手入力ボタン**で `issue_manual_costs` に直接追加。
- 該当案件の**売掛（売上）**が登録されていれば、**収支（売上 − コスト合計）** も表示。
- 集計は `posting_logic.py` の純粋関数で行い、単体テスト可能にする。

## 8. 横断事項

### 認証
- `common/auth.py` は用意するが、**MVPでは app.py にゲートを掛けない**（誰でもローカルで開ける）。**完成が近づいた段階で有効化**（環境変数 `APP_PASSWORD`）。テレアポアプリで付け外しの実績あり。

### UI
- テレアポの `common/ui.py`（水色モダン・Noto Sans JP）を流用。ホームに機能カードを並べる。

### OCR（bedrock_client.py 拡張 ＋ ocr.py）
- Bedrock Claude（`jp.anthropic.claude-haiku-4-5-...`）の messages API に**画像コンテンツブロック**を渡せるよう `invoke_model` を拡張。
- `ocr.py` がレシート/請求書画像を受け取り、プロンプトで「日付・金額・品目（買掛は取引先候補も）」をJSON抽出。抽出は下書き、人が確認・修正して登録。

### データ永続化とバックアップ
- SQLite（`data/posting.db`）。`db_sync.py` により `DB_S3_BUCKET` 設定時はS3同期（未設定ならローカルのみ）。`data/` は `.gitignore`。

### テスト
- `posting_logic.py`（集計・部数計算・収支）と `invoice_excel.py`（請求書流し込み）を中心に **TDDで単体テスト**。実データE2Eで回帰確認。UIは Playwright で実機確認。
