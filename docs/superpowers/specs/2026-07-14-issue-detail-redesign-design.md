# 号別明細ページ 改修設計書（配布員代を日ごと・作業別／雑費を自動集計）

- 日付: 2026-07-14
- 対象: `pages/03_号別明細.py`（と `common/posting_store.py` / `common/posting_logic.py` の一部）
- 目的: 紙の管理表「YYYY年M月　号別明細.xlsx」の感覚に近づけ、
  「その号の配布にいくら使ったか」を一目で分かるようにする。

## 背景・現状

現行の号別明細ページ（`03_号別明細.py`）は、選択した号（案件=project）に紐づく
コストを **小口 / 買掛 / 業務委託 / 手入力** の4バケットで集計し、
コスト合計と収支（売上−コスト）を表示している。

一方オーナーの既存管理表（`2026年6月　号別明細.xlsx`）は号ごとに1シートで、
- **配布員代（人件費）を日付ごと**に、作業（倉庫/丁合作業/挟みこみ/配布/単独配布）単位で並べ、
  日ごと小計を積み上げる（例: 6/26号京阪北 計 ¥341,841）。
- **雑費を一番下にまとめる**（レンタカー/ガソリン/高速・駐車/飲み物/外注ネクストレベル、
  各に現金・クレジット等の支払方法）。
- **配布原価（税込）= 配布員代 + 雑費**（例: ¥391,736）。

このレイアウトの「上=配布員代（日ごと）／下=雑費／号の総額」をアプリで再現する。

## 方針（合意事項）

- 配布員代は **日ごと・作業別の集計** で入力・表示する（出勤者ごとの明細は持たない）。
- 雑費は **既存の 小口・買掛・業務委託 から自動集計**（この号に紐づくものを集める。二重入力なし）。
- **号の総額（配布原価 税込）は今のコスト合計と同額**。グループの見せ方だけを変える:
  - 旧「手入力コスト」→ **配布員代（日ごと・作業別）** に格上げ（日付・作業を持たせる）。
  - 旧「小口＋買掛＋業務委託」→ **雑費** としてまとめて自動集計。

## データモデルの変更

### 1. `issue_manual_costs` を「配布員代（日ごと・作業別）」に拡張
既存: `id, project_id, content, amount, created_at`
- **`work_date TEXT` 列を追加**（配布作業日 YYYY-MM-DD、任意）。旧DBは起動時 `ALTER TABLE ... ADD COLUMN`
  で自動追加（`payables.date` と同じ既存の移行慣例に従う）。
- `content` を **作業（作業内容メモ）** として使う（例: 「丁合・配布」「配布」「単独配布」）。
- `amount` は **その日・その作業の配布員代 合計額**（オーナーが手元集計した金額を入力）。
- 既存の手入力行（`work_date` なし）は「日付なし」として一覧末尾にそのまま表示（後方互換）。

store 変更:
- `add_issue_manual_cost(project_id, content, amount, *, work_date=None, ...)` に `work_date` を追加。
- `list_issue_manual_costs(...)` は `work_date` を含めて返し、**work_date 昇順（None は末尾）→ id 昇順** で並べる。

### 2. 雑費の支払方法判定（新規の純粋関数）
`common/posting_logic.py` に `payment_method(source_kind, row) -> str` を追加（表示用ラベル）:
- 小口(petty) → **「現金」**
- 買掛(payable) → `original_status` から判定: 「クレジット」を含む→**「クレジット」**、
  「振込」を含む→**「振込」**、それ以外/未設定→**「買掛」**。
- 業務委託(contract) → **「振込」**（外注への請求払い）。
純粋関数として単体テスト可能にする。

## 画面構成（`03_号別明細.py`）

上から順に:

1. **号（案件）選択**: 既存の pills を踏襲。期間指定 pills も踏襲（全期間/今年/今月/今週/指定）。
2. **上部サマリー（メトリクス）**:
   - **配布原価（税込）** = 配布員代小計 + 雑費小計（大きく表示）。
   - 補助表示: 配布員代小計 / 雑費小計 の2枚。
   - 売上がある号のみ **収支（売上−配布原価）** を delta 付きで表示（既存ロジック流用）。
3. **配布員代（日ごと・作業別）** 〔配置: 上〕
   - 表: **日付 / 曜日(work_date から自動) / 作業 / 金額**、work_date 昇順。
     同一日に複数行（作業別）を許容し、**日ごとの小計行**を挟む。最下に **配布員代 小計**。
   - 追加フォーム: **日付 / 作業 / 金額** →「追加」（`clear_on_submit`）。
   - 各行 **削除** 可（`st.data_editor` もしくは行ごと削除ボタン。既存UIに合わせ後者を基本）。
   - CSV/Excel 出力（`section_export`）。
4. **雑費（自動集計）** 〔配置: 下〕
   - この号に紐づく **小口 + 買掛 + 業務委託** を1つの表に統合表示。
   - 表: **項目 / 金額 / 支払方法 / 日付(あれば)**。
     - 項目: 小口=費目名（メモ併記可）、買掛=取引先名、業務委託=種別(remark)。
     - 支払方法: 上記 `payment_method` で判定。
   - 最下に **雑費 小計**。CSV/Excel 出力。
5. **出力**: 上記各セクションの `section_export` に加え、
   **「号原価まとめ」** を1枚（配布員代明細＋雑費明細＋合計）で Excel 出力できるボタンを追加。

## 集計ロジック

- `配布員代小計` = この号の `issue_manual_costs.amount` 合計（期間指定時は work_date で期間絞り込み。
  work_date が無い行は「全期間」時のみ計上、これは既存 manual の挙動を踏襲）。
- `雑費小計` = この号の 小口 + 買掛 + 業務委託（既存 `aggregate_issue` の petty/payables/contract 合計）。
- `配布原価（税込）` = 配布員代小計 + 雑費小計（＝旧 `aggregate_issue.total` と同額）。
- 収支 = 売上合計 − 配布原価（既存 `issue_balance` 流用）。

> 総額は不変であることを実データ（`data/posting.db`）または既存テストで確認する。

## 影響範囲・非対象（YAGNI）

- 出勤者ごとの明細入力は **やらない**（日ごと・作業別まで）。
- 支払額の自動計算（日給×/歩合×実績 等）は **やらない**（金額は手入力）。
- 雑費のこのページからの直接入力は **やらない**（小口・買掛ページで登録→自動反映）。
- マスタや他ページ（01/02/04/05）の変更は原則なし。ただし buy 掛の号紐づけ（project_id）は
  既存機能を前提とする。
