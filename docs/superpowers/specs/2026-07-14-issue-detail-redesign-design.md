# 号別明細ページ 改修設計書（配布員代＝業務委託＋直接入力／雑費を自動集計）

- 日付: 2026-07-14
- 対象: `pages/03_号別明細.py` を中心に、`common/posting_store.py` / `common/posting_logic.py` の一部
- 目的: 紙の管理表「YYYY年M月　号別明細.xlsx」の感覚に近づけ、
  「その号の配布にいくら使ったか」を一目で分かるようにする。

## 背景・現状

現行の号別明細ページ（`03_号別明細.py`）は、選択した号（案件=project）に紐づくコストを
**小口 / 買掛 / 業務委託 / 手入力** の4バケットで集計し、コスト合計と収支（売上−コスト）を表示する。

オーナーの既存管理表（`2026年6月　号別明細.xlsx`）は号ごとに1シートで、
- **配布員代（人件費）を日付ごと・作業別**（倉庫/丁合作業/挟みこみ/配布/単独配布）に並べ、
  日ごと小計を積み上げる（例: 6/26号京阪北 計 ¥341,841）。
- **雑費を一番下にまとめる**（レンタカー/ガソリン/高速・駐車/飲み物/外注 等、各に現金・クレジット等の支払方法）。
- **配布原価（税込）= 配布員代 + 雑費**（例: ¥391,736）。

このレイアウト「上=配布員代／下=雑費／号の総額」をアプリで再現する。

## 方針（合意事項）

- 配布員代は **日ごと・作業別の集計**で扱う（出勤者ごとの明細は持たない）。
- 配布員代は **2つの入力経路**を持ち、どちらも後から追加できる:
  1. **業務委託ページ（`02_業務委託・請求書.py`）**＝配布員別に「数量×単価」や日給（種別=その他/手当）で
     計算・登録した分（案件=号に紐づく）。**計算式はこちら側**。
  2. **号別明細ページ（`03`）での直接入力**＝日ごと・作業別に金額を手入力した分。
     日給の人・後からの追加はここでも入れられる。**直接入力分は修正・削除も可能**。
- 雑費は **既存の 小口・買掛から自動集計**（この号に紐づくものを集める。二重入力なし）。
- **号の総額（配布原価 税込）は現行のコスト合計と同額**。グループ割り当てだけを見直す:
  - 旧「業務委託 + 手入力」→ **配布員代**（業務委託＋直接入力）。
  - 旧「小口 + 買掛」→ **雑費**。

> グループ再編のみで総額は不変（`業務委託+手入力+小口+買掛` = `配布員代+雑費`）。

## データモデルの変更

### 1. `issue_manual_costs` を「配布員代（日ごと・作業別の直接入力）」に拡張
既存: `id, project_id, content, amount, created_at`
- **`work_date TEXT` 列を追加**（配布作業日 YYYY-MM-DD、任意）。旧DBは起動時 `ALTER TABLE ... ADD COLUMN`
  で自動追加（`payables.date` と同じ既存の移行慣例に従う）。
- `content` を **作業（作業内容メモ）** として使う（例:「丁合・配布」「配布」「単独配布」）。
- `amount` は **その日・その作業の配布員代 合計額**（オーナーが手元で出した金額を入力）。
- 既存の手入力行（`work_date` なし）は「日付なし」として一覧末尾に表示（後方互換）。

store 変更:
- `add_issue_manual_cost(project_id, content, amount, *, work_date=None, ...)` に `work_date` 追加。
- `list_issue_manual_costs(...)` は `work_date` を含めて返し、**work_date 昇順（None は末尾）→ id 昇順**で並べる。
- **`update_issue_manual_cost(id, *, work_date, content, amount)`** を新設（直接入力分の修正）。
- **`delete_issue_manual_cost(id)`** を新設（直接入力分の削除）。

### 2. 雑費の支払方法判定（新規の純粋関数）
`common/posting_logic.py` に `payment_method(kind, row) -> str`（表示用ラベル）を追加:
- 小口(petty) → **「現金」**
- 買掛(payable) → `original_status` から判定: 「クレジット」を含む→**「クレジット」**、
  「振込」を含む→**「振込」**、それ以外/未設定→**「買掛」**。
純粋関数として単体テスト可能にする。

### 3. 業務委託ページ（`02`）
- **変更なし**。現行のまま「配布員×案件(号)×種別×数量×単価」で登録でき、案件(号)に紐づく。
  日給の人は種別=その他/手当で金額を入れる運用で対応（既存機能で充足）。

## 画面構成（`03_号別明細.py`）

上から順に:

1. **号（案件）選択**: 既存の pills を踏襲。期間指定 pills も踏襲（全期間/今年/今月/今週/指定）。
2. **上部サマリー（メトリクス）**:
   - **配布原価（税込）** = 配布員代小計 + 雑費小計（大きく表示）。
   - 補助表示: 配布員代小計 / 雑費小計 の2枚。
   - 売上がある号のみ **収支（売上−配布原価）** を delta 付きで表示（既存 `issue_balance` 流用）。
3. **配布員代**〔配置: 上〕。次の2つを表示し、合算して **配布員代 小計**:
   - **(a) 業務委託（配布員別）**: この号に紐づく業務委託の明細（種別/数量/単価/合計）。現行の
     「業務委託（この号の行）」表示を踏襲。
   - **(b) 直接入力（日ごと・作業別）**: `issue_manual_costs`（work_date あり）を
     **日付 / 曜日(自動) / 作業 / 金額**で work_date 昇順表示。同一日に複数行（作業別）を許容。
     - **追加フォーム**: 日付 / 作業 / 金額 →「追加」。
     - **修正・削除**: 直接入力した行は編集（`st.data_editor` で work_date/作業/金額を更新）・削除できる。
   - CSV/Excel 出力（`section_export`）。
4. **雑費（自動集計）**〔配置: 下〕:
   - この号に紐づく **小口 + 買掛** を1表に統合表示。
   - 表: **項目 / 金額 / 支払方法 / 日付(あれば)**。
     - 項目: 小口=費目名（メモ併記可）、買掛=取引先名。
     - 支払方法: 上記 `payment_method` で判定。
   - 最下に **雑費 小計**。CSV/Excel 出力。
5. **出力**: 各セクションの `section_export` に加え、
   **「号原価まとめ」** を1枚（配布員代＝業務委託＋直接入力／雑費／合計）で Excel 出力するボタンを追加。

## 集計ロジック

- `配布員代小計` = この号の 業務委託合計 + 直接入力(`issue_manual_costs`)合計。
  - 期間指定時: 業務委託は発行日、直接入力は work_date で期間絞り込み。
    work_date が無い直接入力行は「全期間」時のみ計上（既存 manual 挙動を踏襲）。
- `雑費小計` = この号の 小口 + 買掛（既存 `aggregate_issue` の petty/payables 合計）。
- `配布原価（税込）` = 配布員代小計 + 雑費小計（＝旧 `aggregate_issue.total` と同額）。
- 収支 = 売上合計 − 配布原価。

> 総額が現行と一致することを実データ（`data/posting.db`）または既存テストで確認する。

## 影響範囲・非対象（YAGNI）

- 出勤者ごとの明細入力は **やらない**（日ごと・作業別まで）。
- 号別明細ページ側での支払額の**計算式（数量×単価/日給）は持たない**（計算は業務委託ページ）。03は金額を直接入力。
- 雑費のこのページからの直接入力は **やらない**（小口・買掛ページで登録→自動反映）。
- 業務委託ページ・マスタ・他ページ（01/04/05）の変更は原則なし。

## テスト方針（TDD）

- `payment_method` の純粋関数テスト（小口=現金 / 買掛のクレジット・振込・既定）。
- `list_issue_manual_costs` の work_date 昇順（None 末尾）並びのテスト。
- `add/update/delete_issue_manual_cost` の保存・更新・削除・旧DB自動ALTERの後方互換テスト。
- 集計回帰: 配布原価 = 配布員代（業務委託＋直接入力）+ 雑費 が旧 total と一致することのテスト。
- 実機（Playwright/8502）: 号選択→直接入力の追加/修正/削除→日別表示→業務委託の合算→雑費自動集計→配布原価 を確認。
