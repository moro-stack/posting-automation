# 配布コスト管理アプリ マスタ管理 改修（第4弾）設計書

- 日付: 2026-07-21
- 対象: `pages/05_マスタ管理.py`（＋ `common/ui.py` にCSS追加）
- ブランチ: `feature/revisions-4`（`feature/revisions-3` から分岐・第3弾＋第4弾をまとめて実機確認→一括masterマージ）
- 前提: streamlit 1.58.0（`st.dialog` 利用可）。第3弾で導入済みの `active`（有効/停止中）・`count_master_usage`・`master_delete_action`・各 `update_*(active=...)` をそのまま使う。

## 背景・目的

第3弾でマスタに「編集／削除（停止中方式）」が付いたが、UIが以下の点で使いにくい:
- 買掛先・業務委託は上に読み取り専用テーブル、下に操作用の行リストが分かれていて二度手間。
- 現在のステータス（有効／停止中）が一覧の行から分からない（停止中は折りたたみの中に隠れる）。
- 編集フォーム・新規登録フォームがページ内に縦積みされ、一覧が下に伸びて見にくい。

**目的**: マスタ管理を「1行＝1マスタ、その行でステータスが分かり、その行から編集できる」形に整理し、新規登録・編集は別窓（モーダル）に追い出して一覧をすっきりさせる。

## スコープ

対象＝マスタ管理の**全5タブ**（案件・費目（小口）・買掛先・売掛先・業務委託）。
他ページ（01〜04）は変更しない。データ層（`posting_store` / `posting_logic`）のスキーマ変更は**なし**（第3弾の `active` 等を再利用）。

## 変更点

### 1. 一覧の行レイアウト（全5タブ共通）

各マスタ1件を1行で表示する。読み取り専用テーブル（`nice_table`）は廃止し、この行に一本化する。

```
 [ ＋ 新規登録 ]                                  ← タブ上部・押すと別窓
 ─────────────────────────────────────────────
  <名前>   <主要情報(薄字)>        <ステータス>   [編集]  [🗑]
```

- **名前**: マスタ名（氏名・取引先名・案件名 等）。
- **主要情報（薄字・任意）**: 一覧から中身が分かるよう、名前の右に薄字で補助表示する。
  - 業務委託: `区分・支払形態`（例「業務委託・歩合」）
  - 買掛先: `既定費目 / 原本区分`（空なら出さない）
  - 案件・費目・売掛先: 名前のみ（補助情報なし）
- **ステータス**（下記 2）
- **編集**: 別窓を開く（下記 4）
- **🗑（ゴミ箱）**: 使用実績0件の行だけに表示。確認ダイアログののち物理削除。使用実績1件以上の行には出さない（＝過去データ保護。第3弾の `master_delete_action` 判定をそのまま使う）。

**並び順**: 運用中・停止中を区別せず、同じ一覧に取得順（＝現行の並び）で表示する。停止中の折りたたみ（`_inactive_ui`）は廃止する。

### 2. ステータス・トグル

行のステータス表示自体をクリック可能なトグルにする。

- **運用中（active=1）**: 水色の丸い「運用中」ボタンが脈打って光る。クリック → 確認 → `active=0`（停止中）に更新。
  - 確認の内容は第3弾の停止ロジックを踏襲: 使用実績があれば「過去データを残すため停止中にします（登録の選択肢から消えるだけ）」の説明を出す。使用実績0件でも停止は可能（トグルなので）。
- **停止中（active=0）**: グレーの「停止中」ボタン。クリック → `active=1`（有効に戻す）。こちらは確認なしで即戻す（現行の「有効に戻す」と同じ、破壊的でないため）。
- 更新後は `flash("停止中にしました" / "有効に戻しました", master)` ＋ `st.rerun()`。

**見た目の実装**: `common/ui.py` に専用CSSクラスを追加。運用中ボタンは既存の水色 `--primary` を使い、`@keyframes` で box-shadow を脈打たせる（pulse）。ボタンは `st.button` の実体で、ステータス列に置いたものだけにCSSが当たるようスコープする（Streamlitの行単位ボタン装飾は壊れやすいため、マーカー要素＋隣接セレクタで限定し、8502で目視検証する）。停止中ボタンはグレーの控えめスタイル。

### 3. 新規登録（別窓 / `st.dialog`）

- 各タブの一覧の上に **[＋ 新規登録]** ボタンを置く。押すと `st.dialog` のモーダルが開く。
- モーダルの中身は現行の最下部 `st.form(add_*)` と同じ入力欄（タブごとに異なる）。
  - 案件/費目/売掛先: 名前1欄。
  - 買掛先: 取引先名・既定費目・既定原本区分。
  - 業務委託: 氏名・区分・支払形態・振込先・時給額・月額（現行どおり）。日当金額は登録後に編集モーダルで設定する旨をキャプションで案内。
- 「追加」→ `add_*()` → `flash("○○を追加しました", master)` → `st.rerun()`（モーダルが閉じる）。「やめる」で閉じる。
- ページ下部の旧「追加フォーム」は廃止する。

### 4. 編集（別窓 / `st.dialog`）

- 行の **[編集]** ボタン → `st.dialog` のモーダルでその行を編集。
- 中身は現行の各 `_*_fields(row)` をそのまま流用（ウィジェット key に行idを含める現行の事故防止策も踏襲）。
- **業務委託で支払形態＝日当の場合**: 同じモーダル内に「日当金額の設定」（業務名×金額の `st.data_editor`）も表示し、`replace_daily_rates` で保存する。ページ下部の独立「日当金額の設定」セクションは廃止する。
  - 注意: `st.data_editor` の `num_rows="dynamic"` はモーダル内でも動作する。保存は「更新」時にまとめて行う（氏名等の更新と日当金額の保存を1回の「更新」で反映）。
- 「更新」→ `update_*()`（＋日当なら `replace_daily_rates`）→ `flash("更新しました", master)` → `st.rerun()`。「やめる」で閉じる。

## モーダルの状態管理（技術方針）

- `st.dialog` は同時に1つしか開けない。行ごとの編集は「どの行を編集中か」を session_state に持ち、`if st.button("編集", key=..., on_click=set_target): edit_dialog(master, row)` の形で開く。
- 開いている間に別の行の編集ボタンを押したら対象を切り替える（現行 `_open_edit`/`_edit_slot` の考え方を dialog に移植）。
- モーダル内フォームのウィジェット key には必ず行idを含める（第3弾の教訓＝固定keyだと別行の値が残り、誤って別行へ書き込む事故／2026-07-14）。

## 後方互換・データ

- スキーマ変更なし。`active` は第3弾で全マスタに導入済み。既存の停止中データ（もしあれば）はそのまま一覧にインライン表示されるだけ。
- `pay_type=NULL` の既存請求への影響なし（本改修はマスタ管理画面のUIのみ）。

## テスト方針（TDD）

UIの純ロジック部分を関数に切り出してテストする（Streamlit描画自体はAppTestで補う）。
- ステータス・トグルの遷移: 運用中→停止（確認要否＝使用実績で分岐）／停止中→有効。
- 🗑の表示条件: `master_delete_action(count)=="delete"` の行だけゴミ箱を出す（＝使用実績0件のみ）。
- 主要情報（薄字）の生成: 業務委託＝`区分・支払形態`、買掛先＝`既定費目 / 原本区分`（空欄の畳み方）を純関数化してテスト。
- モーダルのフィールド→update kwargs 変換は現行 `_*_fields` を流用（既存テストがあれば維持）。
- `streamlit.testing.v1.AppTest` でタブ描画・ボタン存在・ダイアログ発火を確認（実データDBのコピー＋別ポート8599／`POSTING_DB_PATH`）。

## 既知の地雷（第3弾までの実証知見・計画に明記）

- **`common/*.py` を変えたら 8502 の手動再起動が必須**（起動batは health=ok なら既存サーバーを開くだけ）。
- Streamlitの**行単位ボタンCSS装飾は壊れやすい**。光る丸ボタンはマーカー＋隣接セレクタでスコープし、必ず8502で目視検証する。
- Streamlitは `<html lang="en">` 固定で自動翻訳が走る → 文字化け/removeChild の原因。`common/ui.py` の翻訳停止は導入済み。
- 検証は**実データDBのコピー**＋別ポート（8599）＋`POSTING_DB_PATH`。`db_sync` は `DB_S3_BUCKET` 未設定なら no-op。
