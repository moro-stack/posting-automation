# 資料作成・変換表 Phase 4 — アドバリュー 報告書化＋京阪南エリア被り判定 設計書

- 日付: 2026-07-22
- 対象: `posting-automation`／ブランチ `feature/shiryo-henkan`
- 位置づけ: 「④資料作成・変換表」の Phase 4。

## 目的
アドバリューの依頼表（町丁目ごとの配布依頼）が、京阪南版の配布エリア（担当地区）と
**被るか／被らないか**を町名＋丁目で正確に割り出し、依頼表＋「担当地区(被り)」列の
報告書を作る。現行はマクロ（`配布地区選別マクロ`）で行っているが**丁目パーサにバグ**があり
（「1丁目・2丁目11～34」等で2丁目以降を落とす／別町に誤マッチ）、これを直して正確化する。

## 入力（2ファイル）
1. **アドバリュー依頼表**: A=GeoCode / B=市区名 / **C=町丁目名(大久保町1)** / D=世帯数15 /
   E=共同住宅主世帯数15 / F=暫定部数 / G=クライアント①○× / H=クライアント②○× /
   I=配布日メモ / J=併配チラシ暫定部数 / K=備考(店舗名) / L=投禁物件 / M=配布日 / N=重複
2. **京阪南版 配送管理表**（京阪北と同じ17列）: **I=担当地区(6桁) / N=町界名 / O=街区(番地)名称**

## マッチングロジック（丁目パーサを正しく直す）
- 依頼表「大久保町1」→ `split_town_choume` で (町名=大久保町, 丁目=1)。
- 京阪南マスタを町界名でインデックス化し、各行の街区から**丁目集合**を `parse_choume_from_gaiku` で抽出:
  - `1丁目1～21`→{1} / `2・3丁目`→{2,3} / `6丁目51～57・7丁目`→{6,7}（番地57を丁目に誤認しない）/
    `1丁目・2丁目11～34`→{1,2}（2丁目を落とさない）/ 丁目表記なし→ワイルドカード（町全体）。
  - 実装のキモ: 「丁目」で分割し、**先頭は素の数字全部＝丁目**、**途中セグメントは末尾の素の数字だけが次の丁目**（`51~57・7`→7のみ、`51~57`は前の丁目の番地）。
- 町名は完全一致優先、無ければ「町」サフィックス有無を吸収（依頼表「大日」＝京阪南「大日町」）。
- 丁目が一致する京阪南の担当地区を**複数可**で返す（例 大久保町1→913101・913102＝番地で分割）。マッチ有=**被り**、無=**非被り(未マッチ)**。

## 出力（報告書Excel・1シート）
ヘッダー: 町丁目名／市区名／**担当地区(被り)**／**被り**／世帯数15／暫定部数／クライアント①／クライアント②／配布日メモ／併配部数／店舗名／投禁物件／配布日。
※現行「3_完成出力」はヘッダーと中身がズレた壊れテンプレなので踏襲せず、正しいヘッダーで新規生成。
※クライアント名は案件ごとに変わる＆実名なので、列名は汎用「クライアント①/②」（○×データはそのまま）。

## 検証
- 単体テスト（丁目パーサの全エッジケース／マッチング／報告書生成）。
- **実データ通し**（アドバリュー用.xlsm の 2_配布依頼＋1_地区マスタ）: 71エリア→被り48/非被り23。
  現行マクロ（3_完成出力）と突合: **67一致＋マクロの取りこぼし3件を救済（佐太中町2・7等）＋マクロの誤マッチ1件を回避（大日町3→京阪南に3丁目無し＝正しく未マッチ）**＝**私の判定が全71件で正しい**。
- **実機ブラウザE2E**: 2ファイルアップロード→「71エリア/被り48/非被り23」→報告書DL→大久保町1(913101・913102)・佐太中町2(923101)・大日町3(未マッチ)を目視一致。
- データ安全: モジュール/テストに実クライアント名・実店舗名なし。
