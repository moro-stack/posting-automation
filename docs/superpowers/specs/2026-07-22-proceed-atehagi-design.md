# 資料作成・変換表 Phase 3 — リビングプロシード あて紙 設計書

- 日付: 2026-07-22
- 対象: `posting-automation`／ブランチ `feature/shiryo-henkan`
- 位置づけ: 「④資料作成・変換表」の Phase 3。Phase 1（京阪あて紙）に続く。

## 目的
リビングプロシードの「配布依頼書兼終了報告書」（エリア×広告主のマトリクス）をアップロードすると、
担当地区（エリア/配布ブロック）ごとに1枚のあて紙をまとめたExcelを生成する。
現行は大橋さん提供のあて紙xlsx（`ｒ専用リビング新聞豊中 あて紙.xlsx`）を手作業＋数式で作っている。

## 入力仕様（実物 2025.8.29号【高槻・茨木】で確定）
- I1: タイトル「配布依頼書 兼 配布終了報告書【高槻・茨木】」→ **エリアグループ＝【】の中**
- A2: 「2025年08月29日号 …」→ **号**
- 2行目 G2:O2 = **広告主名（チラシ名）**／5行目 G5:O5 = **サイズ**（P列「チラシ枚数」の手前まで走査）
- 明細は9行目から **2物理行＝1エリア**（奇数行＝データ）:
  - A=件数 / B=エリアコード（高槻-2-1）/ F=媒体部数 / G:O=広告主別部数、次の偶数行 B=町名
  - 「合 計」行（Aが数値でない）で明細終了
- CSV/xlsx 両対応（cp932優先。読取は `common.atehagi.read_uploaded` を再利用）

## 出力仕様（`ｒ専用リビング新聞豊中 あて紙` FMT 踏襲）
- テンプレ `templates/あて紙テンプレート_リビング.xlsx`（豊中-2-1シートを**数式全消し・データレス化**して同梱）
- **1エリア＝1シート**（シート名＝エリアコード）。印刷範囲 B1:I50・縦。
- セル: F3=エリアグループ / E4=エリアコード / G2=媒体部数 / **6行目 媒体行 C6「リビング」・H6「ﾀﾌﾞﾛｲﾄﾞ」・I6=媒体部数** / 7行目以降=**部数>0の広告主**（C=広告主名・H=サイズ・I=部数）/ **I48=チラシ数**（部数>0の広告主件数）
- ファイル名: `リビングプロシード_あて紙_{グループ}_{YYYYMMDD}.xlsx`

## 確定した判断（オーナー承認）
1. 媒体「リビング」のサイズ＝**ﾀﾌﾞﾛｲﾄﾞ固定**
2. G2/I6の部数＝**F列（媒体部数＝各戸＋集合）**
3. あて紙に載せる広告主＝**部数>0のものだけ**

## モジュール構成
- `common/proceed_atehagi.py`（純関数：`parse_haifu_irai` / `build_proceed_atehagi_workbook` / `proceed_atehagi_filename` / `read_and_parse`）
- `pages/07_資料作成・変換表.py` に「リビングプロシード あて紙」タブ追加
- `templates/あて紙テンプレート_リビング.xlsx`（データレス）
- `tests/test_proceed_atehagi.py`（合成フィクスチャ・実名なし）
- `scripts/extract_proceed_template.py`（テンプレ再抽出用）

## 検証
- **京阪と違い“同一依頼書から作った正解あて紙”が手元に無い**（豊中は別号・数式駆動）ため、ゴールデン突合は不可。
- 単体テスト（parse/build/決定性/filename）＋実物の配布依頼書で通しテスト＋**実機ブラウザE2E**（高槻・茨木＝広告主6社/エリア21件→21シートのあて紙、セル目視一致）で確認。最終はオーナー目視。

## 残・今後
- 各戸/集合ポスト（D/E列）の内訳はあて紙に出さない（F媒体部数のみ）。必要なら追加。
- 号やエリアで媒体サイズがタブロイド以外になるケースが出たら、媒体サイズを可変化。
- 他のプロシード号（豊中・吹田/高槻・茨木以外）でも同じ様式か、実物で追検証推奨。
