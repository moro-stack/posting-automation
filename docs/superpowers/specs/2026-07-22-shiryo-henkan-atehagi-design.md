# 資料作成・変換表 機能 — 設計書（Phase 1: 京阪北/南版 あて紙）

- 日付: 2026-07-22
- 対象アプリ: `posting-automation`（配布コスト管理・大阪支社アプリ）
- 依頼: 既存アプリに「④資料作成・変換表」機能を追加。マスタ＝関西ぱど京阪北版/南版・アドバリュー・リビングプロシード。
- 本書のスコープ: **Phase 1 = 関西ぱど京阪北/南版の「あて紙」自動生成**（CSV→あて紙）。他は末尾のロードマップに記載。

---

## 1. 背景・目的

現在、京阪北版のあて紙は Excel マクロ（`@マクロ（京阪北版）あて紙　マスタ.xlsm` の VBA `Module2`）で作成している。
関西ぱどから届く「配送管理表」を1枚目シートに貼り付け → マクロ実行 → 担当地区コードごとに1枚ずつ、約350枚のあて紙シートを生成する運用。
これをアプリ上の「配送管理表 CSV をアップロード → あて紙 Excel をダウンロード」に置き換え、マクロ入り xlsm を配らずに誰でも作れるようにする。

**現行マクロと1枚も違わない出力**を最優先要件とする（下流＝印刷してチラシ束に添付、を変えないため）。

---

## 2. スコープ

### Phase 1（本書で実装する範囲）
- 関西ぱど**京阪北版**の配送管理表 CSV → あて紙 Excel（完成）
- **京阪南版**は「配送管理表フォーマットは北版と同一・地区名の割り当てルールのみ異なる」（オーナー確認済）。エンジンは版設定（地区名ルール）を差し込む形にし、**北版を完成**させる。南版は地区名ルール1点を受領し次第、設定追加のみで有効化。

### 本書で実装しない範囲（Phase 2〜4・様式/ロジックは解析済み）
- Phase 2: 京阪の**報告書・集計表・実績表**
- Phase 3: **リビングプロシード**（配布依頼書兼終了報告書アップロード → あて紙）。発行元＝㈱リビングプロシード大阪支社。
- Phase 4: **アドバリュー**（依頼表→報告書化＋京阪南版との**エリア被り/非被り判定**）。突合キー＝町名＋丁目番号。丁目パーサの精緻化が必要（現行マクロは複数丁目表記で取りこぼしあり）。

## 3. 入力仕様（確定・実データで検証済み）

関西ぱどから届く「配送管理表」。実物＝`@マクロ（京阪北版）あて紙　マスタ (1).xlsm` の1枚目シート `京阪北_その他配送管理表`（今回検体＝1248号・配布日2026-06-26・1,738データ行）。

- **形式**: CSV を第一とする（xlsx も受け付ける）。エンコーディングは **cp932（Shift-JIS）優先・utf-8-sig フォールバック**（実CSV到着時に実測して確定）。
- **レイアウト**: 先頭行＝表題（`配送管理表 / 日付 / (1248号) / 作成日:...`）、**2行目＝ヘッダー**、3行目以降＝データ。
- **列（17列, A→Q / 0-indexed）**:

| idx | 列名 | あて紙で使う | 備考 |
|---|---|---|---|
| 0 | 配布日 | (任意) | ファイル名・見出しに利用可 |
| 1 | 号数 | (任意) | ファイル名に利用（例 1248号） |
| 2 | ルート | - | |
| 3 | 異動 | - | |
| 4 | 配送順位 | - | |
| **5** | **ぱどんな** | **A3** | 担当リーダー名。**生CSVに全行入っている**（空欄0）。7種の実値あり |
| 6 | 住所 | - | 空が多い |
| 7 | 電話番号 | - | 空が多い |
| **8** | **担当地区** | **D4・グループキー** | 5桁コード。**1地区＝あて紙1枚** |
| 9 | チラシコード | - | |
| **10** | **配送物** | **B5:B18** | 例「01 ぱど」「京都生協」 |
| **11** | **配布部数** | **G2・J5:J18** | |
| 12 | 配送備考 | - | |
| 13 | 町界名 | (任意) | 例「大住ヶ丘」 |
| 14 | 街区（番地）名称 | (任意) | 例「1丁目」 |
| 15 | 受注種別 | - | 例「全戸配布(チラシ)」 |
| **16** | **チラシサイズ** | **I5:I18・I18件数** | 例「Ｂ４(折済)」 |

- **重要な確定事項**: リーダー名（ぱどんな）は生CSVに含まれるため、**地区→リーダーの別マスタは不要**。生CSVだけであて紙が完結する。
  - 例外運用: ごく稀に1地区のリーダーを手動で足す（検体では地区46501に「クローバージャパン」を追記）。→ UIに**任意の「ぱどんな上書き」**を用意（地区コード指定で置換）。必須ではない。

## 4. 変換ロジック（純関数・`common/atehagi.py`）

現行 VBA `Module2`（`担当地区別_あてがみテンプレ反映_完全版_軽量`）の再現。

1. **パース** `parse_haisou_kanri(bytes|df) -> list[dict]`
   - ヘッダー行（2行目）を検出し、17列を上表の意味にマッピング（列名一致＋位置フォールバック）。
   - 各データ行を `{padonna, chiku, haisoubutsu, busuu, size, ...}` に正規化。
2. **地区コード正規化** `area5(chiku) -> str`
   - 文字列から数字のみ抽出し末尾5桁（VBA `GetArea5` 同等）。
3. **グループ化** `group_by_chiku(rows) -> OrderedDict[chiku -> list[row]]`
   - 担当地区コードをキーに、**元の出現順を保持**して束ねる（並べ替えない）。
   - 各グループ先頭行＝「01 ぱど」基準行（サイズ空・部数のみ）。
4. **地区名ルール（版設定）** `chiku_name(version, chiku) -> str`
   - 京阪北版（現行Module2）: 担当地区コード**先頭1桁**で判定 → `1/2/3 → 枚方・交野`, `4/5 → 寝屋川・枚方`。
   - 京阪南版: **地区名ルールのみ後日受領**して同型で追加（未確定＝§10）。
   - ※ VBAには旧版 `Module1`（1/2→守口・門真, 3/4/5→寝屋川・枚方）もあるが**現行はModule2**。
5. **チラシ数集計**: グループ内で**チラシサイズが非空の明細件数**（I18）。

すべて DB 非依存・`streamlit` 非依存の純関数として実装し、TDD（`tests/test_atehagi.py`）で先にテストを書く。

## 5. 出力仕様（あて紙・現行踏襲）

### テンプレート
現行 `.xlsm` の `あてがみ` シートを**切り出して** `templates/あて紙テンプレート_京阪.xlsx` として同梱（体裁・結合セル・印刷設定を保持）。

### セルマッピング（1あて紙＝1シート, 印刷範囲 A1:J18・A4縦・1ページ）
結合セル: `A3:E3` / `D4:G4` / `G2:I2`（**書込みは左上セルのみ**）

| セル | 内容 | 供給元 |
|---|---|---|
| A1 | 地区名 | `chiku_name(version, chiku)` |
| A3 | ぱどんな（担当リーダー） | グループ先頭行の ぱどんな(5) |
| A4 | 「担当地区　：　」 | 固定 |
| C4 | 0 | 固定 |
| D4 | 担当地区コード（5桁） | グループキー |
| G2 | 代表配布部数 | グループ先頭行の 配布部数(11) |
| J2 | 「 部」 | 固定 |
| B5〜B18 | 配送物 | 各明細 配送物(10) |
| I5〜I18 | チラシサイズ | 各明細 チラシサイズ(16) |
| J5〜J18 | 配布部数 | 各明細 配布部数(11) |
| H18 | 「チラシ数：　　」 | 固定 |
| I18 | チラシ数 | サイズ非空件数 |

- 明細は**5行目から最大14行**（B5:J18）。先頭明細＝「01 ぱど」基準行。
- シート名＝担当地区コード（例 `10101`）。同名は上書き/一意化。

### 出力形式（推奨デフォルト）
- **Excel ブック（1地区＝1シート・約350枚）** を1ファイルで生成。現行と同一で、まとめて印刷可能。
- `common/excel_io.freeze_xlsx_bytes()` を通して**DLの決定性を担保**（Streamlitの`/media/<hash>.xlsx`が404になる既知問題の回避）。
- ファイル名例: `京阪北版_あて紙_1248号_20260626.xlsx`（版＋号数＋配布日は CSV から取得）。
- （将来）PDF（1あて紙=1ページ）出力は Phase 2 以降のオプション。

## 6. UI（`pages/07_資料作成・変換表.py`）

- ページ先頭で `apply_app_style()`（既存慣例・自動翻訳抑止）。`st.title("資料作成・変換表")`。
- **マスタ選択**（案件マスタ `projects` の既存プリセット：関西ぱど：京阪北版／京阪南版／アドバリュー／リビングプロシード）。Phase 1では京阪北/南のみ「あて紙」タブを有効化、他は「準備中」。
- 京阪あて紙タブのフロー（既存 `pages/01` の「アップロード→data_editorレビュー→生成」型を踏襲）:
  1. `st.file_uploader`（type=`csv, xlsx`）で配送管理表をアップロード。
  2. **版（北/南）** を選択（既定はファイル名/シート名から推定・手動変更可）。
  3. パース結果のサマリを表示（総行数・地区数・号数・配布日・リーダー内訳）。
  4. （任意）「ぱどんな上書き」＝地区コード指定で置換。
  5. **「あて紙を生成」** → ブックを `st.download_button` で提供（freeze済）。
- エラーは1件で止めない（`try/except`・進捗表示）。

### 既存の落とし穴（遵守）
1. 生成xlsxは**必ず `freeze_xlsx_bytes`**（未通過はDL 404）。
2. **結合セルは左上セルのみ書込み**（従セルは read-only 例外）。
3. openpyxlは **`.value=` 代入**（`cell(r,c,value=...)`は使わない）。`value=None`で消す時は属性代入。
4. CSV読取は **cp932優先**、CSV出力は utf-8-sig（BOM）。
5. 日本語は端末直出力せずファイル(utf-8)経由で確認。

## 8. 検証（ゴールデン突合＝最重要）

現行 `.xlsm` には、**同じ配送管理表(1,738行)からマクロが生成した正解あて紙 353枚**（シート `10101`…`57805`）がそのまま入っている。これを**正解データ**とする。

- **パリティテスト**: 同じ配送管理表を入力に `common/atehagi` が生成したあて紙を、353枚の正解シートと**セル単位で突合**（A1/A3/D4/G2/B5:J18/I18 等）。1セルでも不一致なら失敗＝「現行マクロと完全一致」を機械保証。
- **データ保護**: 公開リポジトリに実配送データを丸ごとコミットしない。テストは
  - (a) **合成フィクスチャ**（構造だけ模した少数地区の擬似データ＋期待あて紙）を `tests/fixtures/` に置き、CIでも回る単体テスト。
  - (b) **フル突合**は「ローカルに実 `.xlsm` があれば実行、無ければ skip」の任意テストとして実装（開発機での一致確認用）。
- **決定性テスト**: 生成xlsxの md5 が2回一致（`freeze_xlsx_bytes` 検証・`test_invoice_excel` 同型）。
- AppTest スモーク（`tests/test_pages_smoke.py` 型）で新ページが例外なくレンダリングされること。

## 9. 非機能・運用

- ローカル 8502 では従来どおり無ゲート。Cloud（デモ）では影響なし（あて紙生成は入力アップロード専用でDB非依存）。
