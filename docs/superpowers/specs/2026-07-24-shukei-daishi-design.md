# 京阪南北版 集計表を「実物レイアウト」で出力（build_shukei_workbook 刷新）

- 日付: 2026-07-24
- 対象: `posting-automation` ／ ブランチ `feature/jisseki-daishi`（実績表と同ブランチで継続）
- 種別: 既存機能「資料作成・変換表 > 京阪あて紙タブ > 集計表」の出力レイアウト刷新

## 1. 背景・目的
- 大阪支社が実際に使う集計表は `関西ぱどアプリ開発資料/関西ぱどアプリ開発.xlsx` の `集計表` シート（京阪北 1248号）。
- 現行 `build_shukei_workbook` は縦並びの簡易リスト出力で、実物の密な帳票レイアウトと違う。
- 目的：**数値は既存 `shukei_data`（実データ京阪北1248号で全項目一致を検証済）をそのまま使い**、出力を実物帳票レイアウトに載せ替える。

## 2. 数値の検証結果（2026-07-24・京阪北1248号で突合）
`shukei_data` の値は実物集計表の各セルと **折チラシ以外すべて一致**（NG 0件）:
- 総地区353／総配布部数148,232／帳合127,051／挿込138,625／ぱどのみ9,607／チラシ総数552,815
- チラシ種類数別(0〜9種)の地区数・部数、エリア別部数(1〜5)、上部マトリクス(例 aim: 37地区/13,743部)すべて一致。
- **折チラシ（B3,B4）=88,249 のみ再現不可**。実物セルは数式でなく手打ち。約20通りの逆算・全18列調査でも一致せず。
  → オーナー確定（2026-07-24）：**折チラシのセルは空欄（"—"）にして手入力**。他は全自動。

## 3. データモデル
`shukei_data(groups, version)` を**そのまま利用**（変更なし）。返す構造:
- `per`: {(area, leader): {"chiku": 地区数, "busuu": 部数, "by_type": {チラシ種類数: [地区数, 部数]}}}
- `area_busuu` / `area_chiku`: {area(先頭1桁 "1".."5"): 部数 / 地区数}
- `type_dist`: {チラシ種類数(0..11): [地区数, 部数]}
- `total_chiku` / `total_busuu` / `chirashi_sou` / `pado_only_busuu` / `choai_busuu` / `sashikomi_busuu`

area は `area_no`（京阪北=先頭1桁、南=先頭2桁・CSV値そのまま）。リーダーは `pado_row` の padonna。

## 4. レイアウト仕様（新 build）
新規 `build_shukei_daishi_workbook(data, version, gou, haifubi) -> bytes`（旧 `build_shukei_workbook` を置換）。

### 4.1 タイトル部（1行目）
- `A1`（結合 A1:E1）= 版名（`_VERSION_LABEL`、例「京阪北版」→表示は「京阪北」でも可。実物準拠で版名）。太字。
- `G1`（結合 G1:AE1）= `{M/D} 号　{配布期間}`。配布期間は分からなければ `{M/D}号` のみでよい（配布期間は任意）。太字。

### 4.2 上部マトリクス（エリア×リーダー×チラシ種類数）
- ヘッダー行（3行目）: `A3=エリア` `B3=リーダー` `C3=チラシ種類` `E3=コース数` `AG3=配布部数` `AH3=地区数`（太字・罫線）。
- 本体（4行目〜）: エリアを 1→5 昇順、その中でリーダーを列挙（`per` のキーから area 別に集約。リーダー順は部数降順など安定順で可）。
  - 各リーダーの `by_type` を**チラシ種類数の昇順**で並べ、1エントリ＝〔チラシ種類数・"-"・コース数・部数〕の4セル。
  - **横に最大6エントリ/行**で並べ、超えたら次の行に折り返す（リーダーは複数行になりうる）。
  - **ブロックkの開始列** = `3 + k*5`（k=0..5 → C, H, M, R, W, AB）。各ブロック4列＝〔チラシ種類数, "-", コース数, 部数〕、間の1列（G/L/Q/V/AA）は余白。
  - `AG`（列33）= そのリーダーの `chiku`… ではなく **配布部数計 `per[..]["busuu"]`**、`AH`（列34）= **地区数計 `per[..]["chiku"]`**。リーダーが複数行にまたがる場合は AG/AH をその範囲で縦結合。
  - `A`（エリア番号）はそのエリアの全リーダー行を縦結合、`B`（リーダー名）はそのリーダーの行を縦結合。
  - エリアの区切りに空行を1行入れてよい（実物準拠・任意）。
- 罫線: ヘッダーと各データセルに細罫。エリア/リーダーの結合セルは中央寄せ。

### 4.3 左下：チラシ種類数別（type_dist）
- チラシ種類数を **11→0 の降順**で1行ずつ: 〔チラシ種類数, "-", 地区数, 部数〕。データが無い種類数(例10,11)は 地区数0・部数0 で行を出す（実物は11..0を全部並べる）。
- 最下段に **総計行**: 地区数 `total_chiku`(353)・部数 `total_busuu`(148,232)。
- 実物では B27〜F39 に配置。新実装では列位置は実物に寄せる（B=チラシ種類数, D=地区数, F=部数, 結合可）。厳密な行番号一致は必須でない。

### 4.4 中下：集計指標
- `帳合` = `choai_busuu`(127,051)
- `挿込`（実物表記「挿み込み」）= `sashikomi_busuu`(138,625)
- `ぱどのみ` = `pado_only_busuu`(9,607)
- `折チラシ（B3,B4）` = **空欄または "—"（手入力用）**
- `チラシ総数` = `chirashi_sou`(552,815)
- 実物では M27〜Q32。ラベル＋値のペアで配置。

### 4.5 右下：エリア別部数
- エリア 1〜5 それぞれ `area_busuu[area]` を「エリアN　部　{部数}」の形で並べる（実物 M35〜S39 準拠）。
- 版名注記（枚方・交野版／寝屋川・枚方版 等）は任意（実物準拠で入れてよいが必須でない）。

### 4.6 体裁・印刷
- 列幅は実物に寄せる（C≈3.6, D≈2.6, E≈4.7, F≈9.2 … の繰り返し、AG≈10.6, AH≈8.6）。
- `orientation="landscape"`、`fitToWidth=1`、`pageSetUpPr(fitToPage=True)`。`print_area` を使用範囲に設定。
- 生成 bytes は必ず `freeze_xlsx_bytes` を通す。
- ファイル名は既存 `shukei_filename(version, rows)` を流用。

## 5. UI（`pages/07_資料作成・変換表.py`）
- 「集計表を生成」ボタンの出力を新 `build_shukei_daishi_workbook(data, version, gou, haifubi)` に差し替え。号・配布日は rows から取得（実績表と同じ流儀）。旧 `build_shukei_workbook` は撤去。

## 6. 検証
- **単体**: `build_shukei_daishi_workbook` を合成データで生成し、(a)ヘッダー、(b)エリア/リーダーの結合と配置、(c)ブロック開始列 `3+k*5`、(d)AG/AH の配布部数計・地区数計、(e)type_dist の11→0行＋総計、(f)帳合/挿込/ぱどのみ/チラシ総数の値、(g)折チラシが空、(h)エリア別部数、(i)印刷=landscape をテスト。
- **実データ突合**（京阪北1248号）: 生成物の主要セルが `shukei_data`（＝実物一致済）の値と一致することを確認。総計353/148,232、帳合/挿込/ぱどのみ/チラシ総数、エリア別、上部マトリクス代表（aim=37地区/13,743部）。
- **南版**でも版名・エリア(先頭2桁 91/92)で出力できること。
- **実機E2E**（別ポート・Playwright）＋**オーナー目視で1枚確認**。
- 既存の全テストは緑（回帰なし）。
