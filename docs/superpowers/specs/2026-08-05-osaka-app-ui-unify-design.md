8. **5件すべて一度に実装する。**
9. **オーナー不在中は「実装＋テストまで」。** 目視確認と master へのマージは戻られてから。

## 3. 設計①　業務完了報告書のA4印刷（G列が切れる）

### 原因（実物で特定済み・推測ではない）

`templates/業務完了報告書兼請求書テンプレート.xlsx` を openpyxl で読み出した結果:

```
print_area = 'Sheet1'!$A$1:$F$27
dims       = A1:G29
列幅        A 6.1 / B 17.9 / C 13.9 / D 12.1 / E 17.5 / F 23.3 / G 8.8
page_setup  orientation=portrait, paperSize=9(A4), scale=85, fitToWidth=None
```

**G列（備考）が印刷範囲の外に置かれている。** 幅不足ではなく、印刷対象に入っていないのが原因。
A〜G の合計は約99.6文字幅 ≒ 7.3インチ。左右余白0.71インチのA4縦で使える幅も約7.3インチあり、さらに縮小85%がかかるため、**印刷範囲にG列を含めれば収まる**。
テンプレート作成時にF列までで範囲を切り、後からG列（備考）を足したものと考えられる。

### 直し方

テンプレートのxlsxを直接書き換えるのではなく、**生成コード側 `common/invoice_excel.build_invoice_xlsx()` で毎回設定する。**

理由:
- テンプレートのバイナリを直すとテストで守れない。コード側ならテストで固定できる。
- 将来テンプレートが差し替わっても設定が効く。

```python
from openpyxl.worksheet.properties import PageSetupProperties

ws.print_area = "A1:G27"
ws.sheet_properties.pageSetUpPr = PageSetupProperties(fitToPage=True)
ws.page_setup.fitToWidth  = 1   # 横は必ず1ページ
ws.page_setup.fitToHeight = 0   # 縦は成り行き
```

- 下端を **27行目** にしたのは実データを確認した結果。28行目は全角スペースのみ、29行目は空。中身の最終行は27行目「現金・振込　支払い済み」。
- `fitToWidth=1` を入れると Excel 側が自動で横1ページに収めるため、今後備考欄を広げても切れない。`scale=85` は fitToPage が有効なとき無視される。
- `orientation=portrait` / `paperSize=9`(A4) は既に設定済みのため変更しない。

### 検証

- 生成した xlsx を openpyxl で開き直し、`print_area` が G列を含むこと・`fitToWidth == 1` を assert。
- **「G列に値が入っている明細行が、すべて print_area の範囲内にある」** ことを assert（列だけでなく行範囲も見る）。
- ミューテーション: `print_area` を `A1:F27` に戻す／`fitToWidth` を消す の2変異で、テストが確実に落ちることを確認してから「直った」と報告する。

### 未確認事項（実装時に実ファイルで確かめる）

`fitToHeight=0`（＝縦は自動）の解釈は Excel のバージョンで揺れることがある。生成物を実際に Excel で開き、印刷プレビューでG列が出ていること・意図せず極端に縮まないことを目視で確認する。問題があれば `fitToHeight=1`（1ページに収める）へ切り替える。

### 新しい共通部品（`common/ui.py`）

```python
def selectable_list(rows, *, key, select_col="選択", id_col="No.") -> tuple[DataFrame, list[int]]:
    """「すべて選択」チェック＋チェック列付きの一覧。(編集後DataFrame, 選択されたid) を返す。
    id_col=None のときは id を持たない一覧とみなし、選択idは空リストを返す。"""

def list_action_bar(edited_df, *, key, title, filename, section=None,
                    select_col="選択", id_col="No.",
                    delete_fn=None, delete_note=None, extra=None) -> None:
    """印刷・ダウンロード・削除を必ず同じ順・同じ見た目で出す。
    delete_fn=None のとき削除だけ無効(灰色)にし、delete_note をホバーで出す。
    extra はページ固有ボタンを右端に足すためのコールバック（業務委託のZIP等）。"""
```

呼び出し側は全ページこの2行になる:

```python
edited, selected_ids = ui.selectable_list(_disp, key="petty")
ui.list_action_bar(edited, key="petty", title="小口一覧", filename="小口一覧",
                   section="petty", delete_fn=store.delete_petty_cash)
```

### 「すべて選択」の実装方針

Streamlit の `data_editor` は外から選択状態を書き換えるのが不安定なため、**チェックボックスを表より前に置き、その値で選択列の初期値を決め、data_editor の key に全選択状態を混ぜて再初期化する**。

```python
all_sel = st.checkbox("すべて選択", key=f"{key}_all")
df[select_col] = all_sel
edited = st.data_editor(df, key=f"{key}_editor_{int(all_sel)}", ...)
```

同じ key の中では個別編集が保持されるため、「全選択してから数件だけ外す」ができる。

### 印刷の動き

1. 🖨 印刷 を押す → `st.session_state[f"_print_{key}"]` に選択行を積んで rerun
2. 立っていれば `list_action_bar` の先頭で**印刷ビュー**を描画して return
   （`<div class="printable">` の中に タイトル・出力日・件数・表・合計）
3. 「印刷する」= 既存 `section_export` と同じ `window.parent.print()`（components.html の iframe から親を印刷。実績あり）
4. 「閉じる」= session_state を消して rerun

`common/ui.py` の `_STYLE` に `@media print` を追加し、印刷時はサイドバー・ヘッダ・ボタン・data_editor・iframe を隠して `.printable` だけ残す。

**合計金額の扱い**: 表示用の値は `"¥1,234"` のような文字列。列名に「金額」「請求額」を含む列があり、**全行が数値としてパースできる場合だけ**合計を出す。1行でもパースできなければ合計行を出さない（嘘の数字を紙に載せないため）。

### 各ページへの適用

| ページ | 対象 | `delete_fn` | 追加ボタン |
|---|---|---|---|
| 01 小口 | 登録済み一覧 | `store.delete_petty_cash` | — |
| 01 買掛 | 登録済み一覧 | `store.delete_payable` | — |
| 01 売掛 | 登録済み一覧 | `store.delete_receivable` | — |
| 02 業務委託 | 登録済み一覧 | `store.delete_contract_invoice` | 報告書まとめZIP |
| 03 号別明細 | 現在 `section_export` を使う2か所（配布員代直接入力・雑費） | `None` | — |
| 06 原価売上まとめ | 現在 `section_export` を使う1か所 | `None` | — |
| 05 マスタ管理 | 行ごとの作りを維持。ボタンの色・形・アイコンのみ統一 | （現状維持） | — |

`delete_fn=None` の画面では `delete_note="このデータは登録画面（小口／買掛／売掛・業務委託）から削除してください"` をホバーで出す。

### 🔴 id列を持たない一覧の扱い（03・06）

01・02 の表示行には `"No."`（＝DBの行id）があるが、**03 号別明細・06 原価売上まとめの表示行は集計結果でありid列を持たない**。
そのため `selectable_list(..., id_col=None)` で呼び、選択idは空リストとする。

これで問題が起きないのは、**印刷とダウンロードは「選択列が True の行」だけを見れば足り、idを必要としないのは削除だけ**だから。
03・06 は `delete_fn=None`（削除は無効）なので、idが無いことによる欠落は発生しない。
逆に言えば **`delete_fn` を渡すページでは `id_col` が必須**であり、`delete_fn` があるのに `id_col=None` の組み合わせは実装時に例外で弾く（無言で「削除したのに消えない」状態を作らないため）。

### 02 業務委託の注意点

`pages/02_業務委託登録.py` は現在ZIP生成を**毎回の再描画で実行している**（240〜264行）。選択行が多いと描画のたびに全件のExcelを作り直すため、共通部品へ寄せる際に **ZIPはボタンを押した時だけ生成する**形に変える。`mark_contract_invoice_exported` の呼び出しタイミング（ダウンロード成功時のみ）は変えない。

## 5. 設計③　クリックしやすさ（依頼②）

### 対象

- `pages/01_経費・買掛・売掛.py:16` — `st.radio("入力の種類", ["小口","買掛","売掛"], horizontal=True)`
- `pages/07_資料作成・変換表.py:22` — `st.radio("版", ["京阪北版","京阪南版"], horizontal=True)`

いずれも `st.segmented_control` に置き換える。連結したトグル状のボタンになり、●の当たり判定ではなくボタン全体が押せる。
「期間」フィルタで既に `st.pills` を使っているため、役割の違いを見た目で分けるために pills ではなく segmented_control を選ぶ。

CSS で最小高さ 44px（スマホのタップ目安）と横paddingを確保する。

### 🔴 置換時に必ず入れるガード

`st.segmented_control` は **選択を解除でき、その場合 `None` を返す**。現在のコードは None を考慮していないため、素朴に置き換えると黙って誤動作する。

```python
# pages/07 の現状 — None が来ると「京阪北版ではない」→ 南版に落ちる
version = A.KEIHAN_KITA if version_label == "京阪北版" else A.KEIHAN_MINAMI
```

版を取り違えると**全枚数のあて紙で地区名が誤る**（コード内のコメントでも警告されている重大な誤り）。
`pages/01` も同様で、None のとき `else` に落ちて「売掛」画面が開いてしまう。

対策: `default=` を指定したうえで、**戻り値が None なら既定値へ明示的にフォールバックし、`==` の連鎖ではなく明示的な対応表で判定する**。

```python
version_label = st.segmented_control("版", ["京阪北版", "京阪南版"],
                                     default="京阪北版", key="keihan_version") or "京阪北版"
version = {"京阪北版": A.KEIHAN_KITA, "京阪南版": A.KEIHAN_MINAMI}[version_label]
```

**テストで固定する**: 「選択が None のとき既定値になる」ことをテストし、ミューテーション（`or "京阪北版"` を外す）で落ちることを確認する。

## 6. 設計④　スマホからのレシートアップロード（依頼⑤）

### 到達手段：社内LAN公開

`起動_大阪支社アプリ.bat` の Streamlit 起動引数に `--server.address 0.0.0.0` を追加する（現在は既定の localhost のみで待ち受けているため外から届かない）。

```
'run','app.py','--server.port','8502','--server.address','0.0.0.0','--server.headless','true'
```

起動完了後、bat が PC の LAN IP を取得して案内を表示する:

```
スマホからは同じWi-Fiで  http://192.168.x.x:8502  を開いてください
```

- 実データの入った `data/posting.db` にそのまま登録される（コピーではない）
- PCでアプリが起動している間だけ使える
- 初回は Windows ファイアウォールの許可ダイアログが出る可能性がある。bat にその旨を1行表示する
- 共有パスワードは**かけない**（2章の確定事項7）

### アプリ側のスマホ対応

1. **カメラ撮影**: `pages/01` の小口登録に `st.camera_input("その場で撮る")` を追加。撮った画像は既存の `_ocr_files()` フローにそのまま乗せる。
   ⚠️ `st.camera_input` の戻り値はファイル名が実質固定で拡張子から MIME を決められないため、`ocr.media_type_for(name)` を通さず **`image/jpeg` 固定**で `ocr.extract_receipt` に渡す。
2. **スマホ幅のCSS** を `common/ui.py` の `_STYLE` に追加（`@media (max-width: 640px)`）:
   - `.block-container` の左右パディングを縮める
   - `list_action_bar` のボタンを縦積みにする
   - 表を横スクロールできるようにする
   - サイドバーは既定で畳む
