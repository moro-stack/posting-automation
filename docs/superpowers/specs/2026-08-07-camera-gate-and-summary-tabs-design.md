# 小口カメラのボタン化 ＋ 原価売上まとめのタブ分け 設計

作成: 2026-08-07 ／ ブランチ: `feature/camera-and-summary-tabs`（`feature/demo-share` から分岐）

オーナー依頼（2026-08-07）の 4 件のうち **A** にあたる。B（集計表のデザイン実物化）・
C（仕分け表・新機能）・D（あて紙のタブ名と南北入れ替え）は別スペックで扱う。

## 背景

1. **カメラが常時起動している。** 小口のページを開くと、PC でも内カメラが起動しっぱなしになる。
   オーナーの言葉：「内カメラで仕事の様子とられるのやだ」「常時カメラが向いてると気が散る」。
2. **原価と売上が 1 つの一覧に混ざっている。** 原価売上まとめの明細が「区分」列で
   混在しており、どちらを見ているのか分かりにくい。

## ゴール

- 小口ページを開いただけではカメラを要求しない。**押したときだけ**起動する（PC・スマホ共通）。
- 原価売上まとめの明細を「原価」「売上」の 2 タブに分ける。

## 非ゴール（やらないこと）

- 買掛・売掛へのカメラ追加（今もカメラは小口だけ。増やさない）
- OCR の読み取りロジックの変更
- 原価の区分をさらに細分化したタブ（オーナー確認済み：2 タブでよい）
- 上部 KPI（売上・原価・利益）のレイアウト変更

## A-1. カメラをボタン式にする

### 原因

`st.camera_input` は **描画された時点でブラウザにカメラ許可を要求する**。
現状 `pages/01_経費・買掛・売掛.py` は小口モードでこれを無条件に描いている（現行 120 行目）。
したがって「ページを開く＝カメラ起動」になる。**描画自体を出し分ければ直る。**

### 挙動

| 状態 | 画面 |
|---|---|
| 初期（オフ） | `📷 カメラを起動` ボタンのみ。**カメラは要求されない** |
| オン | カメラのプレビュー ＋ `撮った写真をAIで読み取る` ＋ `カメラを閉じる` |

- 状態は `st.session_state["petty_camera_on"]`（bool・既定 False）で持つ。
- **閉じるときは撮影データを捨てる。** カメラ部品の `key` に世代番号
  （`st.session_state["petty_camera_gen"]`、閉じるたびに +1）を含め、
  `petty_camera_{gen}` とする。次に開いたとき前回の写真が残っていると、
  ユーザーが撮り直したつもりで**古い写真を読み取る**事故になるため。
- 撮影後の OCR 呼び出し（`ocr.media_type_for_upload` でメディア種別を決める部分）は**変更しない**。

### なぜ `st.toggle` ではなくボタン2つか

`st.toggle` でも実現できるが、オーナーの要望は「**ボタンを押したら起動**」。
オフのときに「起動」、オンのときに「閉じる」と**ラベルが状態を説明する**ほうが、
非エンジニアの利用者に何が起きるか伝わる。トグルは状態を色でしか示さない。

## A-2. 原価売上まとめをタブで分ける

### 区分の割り当て

`common/posting_logic.py` の `company_summary_rows` が付ける「区分」は 5 種類。

| 区分 | タブ |
|---|---|
| 買掛 | 原価 |
| 小口 | 原価 |
| 業務委託 | 原価 |
| 直接入力 | 原価 |
| 売上 | 売上 |

**売上以外はすべて原価**。この対応は `posting_logic` 側に
`SALES_KINDS` / `COST_KINDS` として定数で置き、ページからは参照するだけにする。
ページに `if 区分 == "売上"` を直接書くと、区分が増えたときに
**どちらのタブにも出ない行**が静かに生まれるため。

### 画面

上部 KPI（売上・原価・利益）は**タブの外に据え置き**。全体像は常時見えているべきなので。
その下を `st.tabs(["原価", "売上"])` にする。

各タブの中身は現行と同じ部品構成：

1. `件数・小計` のキャプション（タブごとの合計。分けたら「このタブの合計」が要る）
2. `selectable_list(...)`
3. `list_action_bar(...)`（削除は今どおり灰色・`delete_fn=None`）

キーとファイル名はタブごとに分ける（同じ `key` を使うと data_editor の状態が混線する）：

| タブ | `key` | Excel ファイル名 |
|---|---|---|
| 原価 | `summary_cost` | `原価明細` |
| 売上 | `summary_sales` | `売上明細` |

`id_col=None` は現行どおり（この画面は集計の写しで id を持たない）。

### ミューテーションテスト（省略しない）

テストを書いたら、**わざと実装を壊して落ちることを確かめる**。
「全項目 OK」は、壊して検知できるまで信用しない（2026-07-28 にこれで検証コード自体のバグを発見している）。

壊し方の例：
- カメラを無条件描画に戻す → テスト 1 が落ちるはず
- 閉じても `gen` を増やさない → テスト 4 が落ちるはず
- 原価タブのフィルタを「全件」にする → テスト 6・8・11 が落ちるはず
- `COST_KINDS` から「直接入力」を抜く → テスト 10・11 が落ちるはず
