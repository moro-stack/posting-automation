## 1. 現状と実物の差（実測・目視ではない）

`openpyxl` で参照シートの全セルを走査して数えた結果。

| 項目 | 実物 | 今のアプリ（`common/atehagi.py:535` `build_shukei_daishi_workbook`） |
|---|---|---|
| フォント名 | **游ゴシック**のみ | **指定なし** → Excel既定（Calibri） |
| フォントサイズ | **6 / 11 / 12 / 14 / 16 / 18 / 20** の7種 | 既定 ＋ 表題のみ 14 |
| 太字 | ほぼ全セル True | 一部のみ |
| 赤字 `FFFF0000` | **75セル**（チラシ種類数74・版名1） | 版名とチラシ種類数に適用済み |
| 罫線スタイル | **dotted / double / hair / medium / thin の5種** | **thin のみ** |
| 罫線の組み合わせ | 🔴 **146通り** | 1通り（4辺 thin） |
| 列幅 | A=6.2 B=10.7、以降 3.6/2.6/4.7/9.2/3.x を6組 | **指定なし** |
| 行高 | リーダー42.0 / 区切り18〜19 / 下部25.2 / 表題37.2 | **指定なし** |
| 表示形式 | `#,##0_);[Red](#,##0)` | **指定なし**（桁区切りが出ない） |
| 結合セル | 81箇所 | 動的に生成 |

**根本原因**: 今のコードは表をゼロから描いており、書式は「4辺 thin」で一律に塗っている。
レイアウト（どこに何が来るか）は合っているが、**見た目を作る情報が入っていない**。

## 2. 🔴 サイズが固定でないことの実測

「A4一枚に収まる＝毎回同じ行数」ではなかった。手元の実データで数えた上部マトリクスの必要行数：

| データ | 版 | エリア数 | 必要行数 |
|---|---|---|---|
| `アドバリュー用.xlsm`（1_地区マスタ） | 南 | 2 | **5行** |
| `京阪南_その他配送管理表 (1).CSV` | 南 | 2 | **5行** |
| 参照シートの枠 | 北 | — | **22行ぶん** |
| `京阪北版CSV リーダー名あり.xlsm` | 北 | 5 | **23行** |
| `【京阪南】20260821配送管理表 (1).xlsx` | （判定 None） | 6 | **32行** |

**5行〜32行**。参照シートの枠（22行）に収まらないデータが実在する。
したがって「実物シートをテンプレートにして固定セルへ流し込む」方式は成立しない。

## 3. 方針：役割ごとに書式をテンプレートから複写する

書式をコードに直書きせず、**テンプレート `.xlsx` を同梱して実行時に読み取り、
セルの「役割」に応じて複写する。**

### 役割（テンプレートのどの行から書式を採るか）

| 役割 | 書式の採取元（参照シート） |
|---|---|
| 表題（版名・号・配布期間） | 行1 |
| 見出し（エリア/リーダー/チラシ種類/コース数/配布部数/地区数） | 行3 |
| エリア先頭のリーダー行 | 行4 |
| エリア途中のリーダー行 | 行8 |
| エリア末尾のリーダー行 | 行10 |
| エリア区切りの空行 | 行6 |
| 下部集計の各行 | 行27〜39（相対位置で対応） |

行数が足りない場合は**同じ役割の書式をくり返し使う**（22行を超えても崩れない）。
列幅・行高・表示形式・結合の作法もテンプレートから採る。

**利点**: 書式がコードに散らない。将来デザインが変わってもテンプレート `.xlsx` を
差し替えるだけで追随する。「一切変えない」を人の目でなく機械で担保できる。

## 4. 検証方法（目視に頼らない）

参照シートと生成物を **1セルずつ突合**するテストを置く。比較項目：

- フォント名・サイズ・太字・色
- 罫線4辺のスタイル
- 表示形式
- 水平/垂直の揃え
- 列幅・行高
- 結合セルの範囲

**ミューテーションで検出力を確認する**（省略しない）：
- フォントを游ゴシック以外にする → 落ちるはず
- medium を thin にする → 落ちるはず
- 赤字を黒にする → 落ちるはず
- 列幅指定を外す → 落ちるはず
